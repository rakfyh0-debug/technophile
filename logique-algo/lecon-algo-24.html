Algorithmes classiques — Leçon 24

La récursivité (introduction)

Une fonction récursive s'appelle elle-même pour résoudre un problème en le découpant en sous-problèmes plus petits. C'est une technique élégante qui résout naturellement des problèmes complexes — à condition de bien poser le cas de base.

1Qu'est-ce que la récursivité ?

Une fonction récursive s'appelle elle-même à l'intérieur de son propre corps. Elle résout un grand problème en le réduisant à un problème plus petit du même type, jusqu'à atteindre un cas trivial qu'on sait résoudre directement.

L'exemple le plus classique : calculer la factorielle. 5! = 5 × 4!, 4! = 4 × 3!, …, 1! = 1. Chaque étape réduit le problème d'un cran, jusqu'à 1! qui est connu.

Cas de base
La situation simple, connue d'avance, qui arrête la récursion. Sans lui, la fonction s'appelle indéfiniment.
Cas récursif
Le cas complexe qui se ramène à un appel plus petit. Doit toujours progresser vers le cas de base.
Pile d'appels
Chaque appel récursif empile un contexte. Si on dépasse la taille maximale de la pile, on obtient une erreur Stack overflow.
Décomposition
Découper un problème en sous-problèmes plus petits, de même nature. C'est la philosophie de la récursion.

2Exemple : la factorielle

5! = 5 × 4 × 3 × 2 × 1 = 120. En récursif, ça s'écrit très simplement :

fonction factorielle(n) // Cas de base Si n <= 1 alors Retourner 1 Fin Si // Cas récursif Retourner n * factorielle(n - 1) Fin fonction factorielle(5) // = 5 × factorielle(4) // = 5 × 4 × factorielle(3) // = 5 × 4 × 3 × factorielle(2) // = 5 × 4 × 3 × 2 × factorielle(1) // = 5 × 4 × 3 × 2 × 1 = 120

Chaque appel empile un contexte sur la pile. Quand factorielle(1) renvoie 1, les appels se déroulent un par un en remontant et multiplient leur valeur par le résultat reçu.

3Deux autres exemples

Exemple — Somme d'un tableau

La somme d'un tableau, c'est le premier élément + la somme du reste.

fonction sommeRec(tab) Si longueur(tab) == 0 alors Retourner 0 // cas de base Fin Si Retourner tab[0] + sommeRec(tab.sousTableau(1)) Fin fonction sommeRec([1, 2, 3, 4]) // = 1 + sommeRec([2, 3, 4]) // = 1 + 2 + sommeRec([3, 4]) // = 1 + 2 + 3 + sommeRec([4]) // = 1 + 2 + 3 + 4 + sommeRec([]) // = 1 + 2 + 3 + 4 + 0 = 10

Exemple — Fibonacci

Chaque nombre est la somme des deux précédents : 1, 1, 2, 3, 5, 8, 13…

fonction fibonacci(n) Si n <= 1 alors Retourner n Fin Si Retourner fibonacci(n - 1) + fibonacci(n - 2) Fin fonction fibonacci(6) // 8

Fibonacci est un cas classique mais inefficace en récursif pur : beaucoup d'appels sont répétés. On verra pourquoi dans la leçon suivante (complexité).

4Règles d'or de la récursivité

1. Toujours un cas de base
Sans lui, la récursion ne s'arrête jamais → Stack overflow au bout de quelques milliers d'appels.
2. Progresser vers le cas de base
Chaque appel doit se rapprocher du cas de base. factorielle(n - 1) réduit n de 1. factorielle(n) sans modification = infini.
3. Le cas de base doit couvrir tous les cas d'arrêt
Pour factorielle, il faut n <= 1 (pas juste n == 1) pour gérer n = 0 et les négatifs.
4. La profondeur est limitée
Chaque moteur JS limite la profondeur de la pile (souvent ~10 000 appels). Pour de grands n, passer en itératif.

5Pièges fréquents

Oublier le cas de base
La fonction s'appelle indéfiniment. Erreur RangeError: Maximum call stack size exceeded dans la console.
Ne pas progresser
Appeler factorielle(n) au lieu de factorielle(n - 1) → même problème que l'absence de cas de base.
Confondre cas de base et cas récursif
Le cas de base ne rappelle pas la fonction. Le cas récursif rappelle la fonction. Si les deux se ressemblent, il y a un bug.
Trop de profondeur
factorielle(100000) va faire exploser la pile. Pour ces cas, l'itératif est obligatoire.
Récursion inefficace (Fibonacci)
Fibonacci récursif naïf recalcule les mêmes valeurs des milliers de fois. Complexité exponentielle O(2ⁿ). À éviter.
Toute récursion peut devenir itérative
Toute fonction récursive peut s'écrire avec une boucle. La récursion est souvent plus lisible, mais pas plus puissante.
