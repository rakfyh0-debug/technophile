Logique algorithmique — Leçon 4

Lire et écrire (entrées / sorties)

Un algorithme qui ne parle à personne ne sert à rien. Il a besoin de deux gestes : écrire un résultat, lire une donnée. C'est la base de toute interaction.

1Écrire : envoyer vers la sortie

Écrire, c'est envoyer une valeur vers la sortie standard : l'écran, la console, un journal. C'est ainsi que l'algorithme communique son résultat à l'utilisateur.

Écrire (afficher)
Envoyer une valeur vers la sortie. En pseudo-code : Écrire "Bonjour". En JavaScript : console.log("Bonjour").
Sortie standard
Le canal par défaut pour afficher. Historiquement : le terminal. Aujourd'hui : aussi la page web, une notification, un fichier de log.
Concaténation
Coller plusieurs valeurs bout à bout pour former un texte. "Bonjour " + nom → "Bonjour Alice".

On peut afficher du texte brut, ou combiner texte et variables :

Écrire "Bonjour" Écrire "Tu as ", age, " ans" Écrire résultat // En JavaScript moderne (interpolation) : console.log(`Tu as ${age} ans`)

Les backticks ` en JavaScript permettent d'insérer une variable directement dans une chaîne avec ${...}. C'est plus lisible que de coller des morceaux avec +.

2Lire : récupérer depuis l'entrée

Lire, c'est récupérer une valeur depuis l'entrée standard et la ranger dans une variable. C'est ainsi que l'algorithme reçoit les données de l'utilisateur.

Lire (saisir)
Récupérer une valeur depuis l'entrée. En pseudo-code : Lire prénom. En JS navigateur : prompt("Quel est ton prénom ?").
Entrée standard
Le canal par défaut pour saisir. Historiquement : le clavier du terminal. Aujourd'hui : aussi un formulaire HTML, un fichier, une API.
Saisie ≠ valeur typée
Tout ce qui vient d'une saisie utilisateur arrive en texte. Même "25" arrive comme chaîne, pas comme entier. Il faut souvent convertir.

Le principe : on demande, on lit, on range :

Écrire "Quel est ton prénom ?" Lire prénom Écrire "Quel est ton âge ?" Lire âge

Attention : quand on lit, on ne sait pas ce que l'utilisateur va taper. Il peut se tromper, laisser vide, écrire du texte au lieu d'un nombre. C'est le rôle des conditions (Module 2) et de la conversion de type.

3Un algorithme complet : lire puis écrire

Voici un petit programme qui demande le prénom, l'âge, puis affiche un message personnalisé.

Écrire "Quel est ton prénom ?" Lire prénom Écrire "Quel est ton âge ?" Lire âge Écrire "Bonjour ", prénom, ", tu as ", âge, " ans."

Trace d'exécution — avec prénom = "Alice" et âge = 25 :

Étape Action Effet
1Écrire "Prénom ?"L'utilisateur voit la question
2Lire prénomprénom = "Alice"
3Écrire "Âge ?"L'utilisateur voit la question
4Lire âgeâge = "25" (chaîne !)
5Écrire le message"Bonjour Alice, tu as 25 ans."

4Pièges fréquents

Tout est texte à l'entrée
Ce qui vient d'une saisie utilisateur arrive en chaîne. Pour calculer avec, il faut convertir : Number("25") → 25.
Oublier de valider
Rien ne garantit que l'utilisateur tape un nombre. "abc" transformé en Number donne NaN (Not a Number), qui propage silencieusement l'erreur.
Confondre afficher et retourner
console.log affiche dans la console mais ne retourne rien. return renvoie une valeur mais n'affiche rien. Ce sont deux gestes différents.
Message incompréhensible
Afficher 42 tout seul ne dit rien à l'utilisateur. Afficher "Résultat : 42" ou "42 €", oui. Le message fait partie de l'algorithme.

  • • convertirNombre(texte) — convertit une chaîne en nombre ; renvoie null si ce n'est pas convertible
  • • formaterPrix(ht, tauxTva) — renvoie le prix TTC formaté sur 2 décimales, suffixé de " € TTC"
  • • Indices : template literals `...${x}...`, Number(...), isNaN(...), .toFixed(2)
