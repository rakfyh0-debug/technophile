Logique algorithmique — Leçon 6

Les opérateurs de comparaison et logiques

Un algorithme doit savoir décider. Pour cela, il compare des valeurs et combine des conditions. C'est la dernière brique avant les structures de contrôle du Module 2.

1Comparer deux valeurs

Un opérateur de comparaison prend deux valeurs et renvoie un booléen : Vrai ou Faux. Il y en a six à connaître.

Opérateur Signification Exemple Résultat
== égal à 5 == 5 Vrai
!= différent de 5 != 3 Vrai
< strictement inférieur 3 < 5 Vrai
> strictement supérieur 3 > 5 Faux
<= inférieur ou égal 5 <= 5 Vrai
>= supérieur ou égal 3 >= 5 Faux

Retiens la différence entre < et <= : elle est cruciale. 3 < 3 est faux, 3 <= 3 est vrai. Une borne incluse ou exclue change complètement un algorithme.

Prédicat / condition
Une expression qui renvoie Vrai ou Faux. Ex : age >= 18. C'est la brique de base des décisions.
Booléen résultat
Toute comparaison produit un booléen. On peut le ranger dans une variable : estMajeur ← age >= 18.
=== (JS)
En JavaScript, === compare valeur et type, sans conversion. Plus sûr que ==. On y revient en pièges.

Une comparaison s'utilise directement dans une condition :

age ← 20 estMajeur ← (age >= 18) // Vrai note ← 12 estAdmis ← (note >= 10) // Vrai

2Combiner avec ET, OU, NON

Une seule comparaison ne suffit pas toujours. Pour exprimer « l'âge est entre 13 et 17 » ou « c'est le week-end », il faut combiner plusieurs conditions avec des opérateurs logiques.

ET (AND, &&)
Vrai seulement si les deux conditions sont vraies. Sinon Faux. « Je sors s'il fait beau et si j'ai le temps. »
OU (OR, ||)
Vrai dès qu'une des deux conditions est vraie. Faux seulement si les deux sont fausses. « Je sors s'il fait beau ou si j'ai envie. »
NON (NOT, !)
Inverse un booléen. !Vrai = Faux, !Faux = Vrai. « Je sors sauf si il pleut. »

Les tables de vérité disent tout :

A B A ET B A OU B NON A
VraiVraiVraiVraiFaux
VraiFauxFauxVraiFaux
FauxVraiFauxVraiVrai
FauxFauxFauxFauxVrai

Exemples concrets avec les trois opérateurs :

// ET : les deux conditions doivent être vraies estAdo ← (age >= 13) && (age <= 17) // OU : au moins une des deux doit être vraie estWeekend ← (jour == "samedi") || (jour == "dimanche") // NON : on inverse nEstPasVide ← !(texte == "")

Les opérateurs logiques sont la colle entre les comparaisons. Sans eux, on ne peut exprimer que des questions très simples. Avec eux, on construit des décisions complexes.

3Priorité et parenthèses

Quand plusieurs opérateurs se croisent, l'ordre d'évaluation est le suivant (du plus prioritaire au moins) :

  • 1er : parenthèses ( ... )
  • 2e : NON !
  • 3e : comparaisons ==, !=, <, >, <=, >=
  • 4e : ET &&
  • 5e : OU ||

Regarde la différence :

// Sans parenthèses, ET passe avant OU a || b && c // = a || (b && c) // Avec parenthèses, on force un autre ordre (a || b) && c // = (a || b) && c // Exemple complet estAdulteEtInscrit ← (age >= 18) && (inscrit == Vrai)

Comme pour l'arithmétique : en cas de doute, mets des parenthèses. Elles ne coûtent rien, clarifient l'intention, et évitent les bugs de priorité.

4Pièges fréquents

Confondre = et ==
= affecte (« range 5 dans x »). == compare (« est-ce que x vaut 5 ? »). Deux rôles opposés, une lettre de différence.
== vs === en JS
"5" == 5 donne Vrai (JS convertit). "5" === 5 donne Faux (types différents). En JavaScript moderne, on utilise toujours ===.
Inverser ET / OU
« Il fait beau ou j'ai le temps » n'est pas « il fait beau et j'ai le temps ». Une seule erreur de mot change toute la logique.
Loi de De Morgan
!(A && B) équivaut à !A || !B. Et !(A || B) à !A && !B. Utile pour simplifier des conditions.
Court-circuit (JS)
a && b n'évalue b que si a est vrai. a || b n'évalue b que si a est faux. Ça peut masquer des effets de bord.
Oublier les parenthèses
age >= 13 && age <= 17 fonctionne (les comparaisons passent avant ET). Mais a == 1 || b == 2 && c == 3 se lit a == 1 || (b == 2 && c == 3). Ajoute des parenthèses.
