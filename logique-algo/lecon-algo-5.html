Logique algorithmique — Leçon 5

Les opérateurs arithmétiques

Additionner, soustraire, multiplier, diviser, calculer un reste : ce sont les outils de base du calcul dans un algorithme. Bien les connaître, c'est éviter les bugs silencieux.

1Les 5 opérateurs de base

Un algorithme calcule presque toujours quelque chose. Pour cela, il utilise des opérateurs arithmétiques. Il y en a cinq à connaître.

Opérateur Nom Exemple Résultat
+ Addition 7 + 3 10
- Soustraction 7 - 3 4
* Multiplication 7 * 3 21
/ Division 7 / 2 3.5
% Modulo (reste) 7 % 2 1

Le modulo % n'est pas le pourcentage — c'est le reste d'une division entière. On y revient à la section suivante, c'est un outil très puissant.

Expression
Une combinaison de valeurs et d'opérateurs qui produit un résultat : 7 + 3, (a + b) * 2. Une expression a toujours une valeur.
Opérande
Les valeurs de chaque côté d'un opérateur. Dans 7 + 3, 7 et 3 sont les opérandes.
Affectation
Ranger le résultat d'une expression dans une variable : résultat ← a + b.

2Le modulo : l'opérateur méconnu

Le modulo (%) donne le reste d'une division entière. Il répond à la question : « si je divise a par b, qu'est-ce qui reste ? »

7 % 3 // 1 car 7 = 2×3 + 1 10 % 2 // 0 car 10 = 5×2 + 0 (pair) 15 % 5 // 0 car 15 = 3×5 + 0 8 % 4 // 0 car 8 = 2×4 + 0 9 % 4 // 1 car 9 = 2×4 + 1

Le modulo a trois usages très courants en algorithmique :

Tester la parité
n % 2 == 0 → n est pair. n % 2 == 1 → n est impair. C'est le réflexe à avoir.
Découper en paquets
Convertir 155 minutes en heures et minutes : 155 / 60 = 2 (heures), 155 % 60 = 35 (minutes restantes).
Boucler circulairement
Revenir à zéro après un certain nombre : les jours de la semaine, i % 7. Utile pour les rotations.

Le modulo est un outil qui surprend souvent les débutants, mais une fois qu'on l'a compris, on le retrouve partout : horloges, calendriers, cycles, jeux, cryptographie.

3Priorité des opérations

Quand plusieurs opérateurs se croisent, il faut savoir dans quel ordre les évaluer. La règle est la même qu'à l'école :

  • 1er : les parenthèses ( ... ) — toujours en premier
  • 2e : la multiplication * et la division / (et le modulo %)
  • 3e : l'addition + et la soustraction -

Regarde la différence :

2 + 3 * 4 // = 2 + 12 = 14 (multiplication d'abord) (2 + 3) * 4 // = 5 * 4 = 20 (parenthèses d'abord) 10 - 4 / 2 // = 10 - 2 = 8 (10 - 4) / 2 // = 6 / 2 = 3 20 / 2 + 3 // = 10 + 3 = 13 20 / (2 + 3) // = 20 / 5 = 4

En cas de doute : mets des parenthèses. Elles ne coûtent rien, elles rendent l'intention explicite et évitent les bugs de priorité. Un bon algorithme est un algorithme qu'on n'a pas besoin de relire deux fois.

4Pièges fréquents

Division par zéro
En JavaScript : 5 / 0 donne Infinity, 0 / 0 donne NaN. Aucun des deux n'est un résultat utilisable.
Confondre % et pourcentage
50 % 20 donne 10 (le reste), pas 10 % ni 0.10. Le symbole est le même mais le sens est tout autre.
NaN silencieux
Dès qu'un opérande n'est pas un nombre, le résultat devient NaN. Et NaN contamine tout ce qu'il touche. La valeur "5" (chaîne) en est un exemple.
Priorité oubliée
a + b * c ne fait pas (a + b) * c. Toujours se demander quelle opération se fait en premier.
Division entière trompeuse
Dans certains langages, 7 / 2 donne 3 (division entière). En JavaScript, ça donne 3.5. Vérifier le comportement du langage.
