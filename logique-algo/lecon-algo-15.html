Structures de données — Leçon 15

Les tableaux (introduction)

Une variable ne contient qu'une seule valeur. Pour stocker plusieurs valeurs de même nature — une liste de notes, des noms, des températures — on utilise un tableau. C'est la structure de données la plus fondamentale.

1Pourquoi un tableau ?

Imagine que tu doives stocker les notes de 30 élèves. Créer 30 variables note1, note2, note3… note30 ? Impossible à gérer. Un tableau permet de ranger ces 30 valeurs dans une seule variable.

Un tableau, c'est comme une armoire avec des tiroirs numérotés. Chaque tiroir contient une valeur, et on accède à un tiroir par son numéro (son index).

Tableau (array)
Une collection ordonnée de valeurs, rangées dans une seule variable. En pseudo-code : notes ← [12, 15, 8, 17].
Élément
Une valeur individuelle dans le tableau. Le tableau [12, 15, 8] a 3 éléments.
Index
La position d'un élément. Attention : en programmation, on commence à compter à 0, pas à 1. Le premier élément est à l'index 0.
Longueur
Le nombre d'éléments dans le tableau. Se calcule avec longueur(tableau) ou tableau.length en JS.

2Déclarer, lire, écrire

Un tableau se déclare avec des crochets [ ] qui contiennent les valeurs, séparées par des virgules.

// Déclaration notes ← [12, 15, 8, 17, 10] prenoms ← ["Alice", "Bob", "Charlie"] vide ← [] // Lire un élément (par index) premier ← notes[0] // 12 troisieme ← notes[2] // 8 dernier ← notes[4] // 10 // Modifier un élément notes[1] ← 20 // [12, 20, 8, 17, 10] // Longueur Écrire longueur(notes) // 5

Règle d'or : si un tableau a N éléments, les index valides vont de 0 à N-1. Le dernier index n'est jamais N.

3Trois pièges classiques

Piège 1 — Oublier que l'index commence à 0

Le premier élément est à l'index 0, pas 1. Le dernier élément est à longueur - 1.

tab ← [10, 20, 30, 40] tab[0] // 10 (premier) tab[3] // 40 (dernier) tab[4] // ❌ ERREUR, index hors limites

Piège 2 — Accéder à un index hors limites

En JavaScript, si on accède à un index qui n'existe pas, on obtient undefined — pas une erreur. C'est silencieux et dangereux.

tab ← [1, 2, 3] tab[10] // undefined (pas une erreur) tab[-1] // undefined

Piège 3 — Confondre longueur et dernier index

Un tableau de 5 éléments a une longueur de 5, mais son dernier index est 4. Beaucoup de bugs viennent de cette confusion.

tab ← [10, 20, 30, 40, 50] longueur(tab) // 5 dernier index // 4 = longueur - 1 tab[longueur(tab)] // ❌ undefined

4Trois exemples concrets

Exemple 1 — Liste de courses

courses ← ["pain", "lait", "œufs", "fromage"] Écrire courses[0] // "pain" Écrire courses[longueur(courses) - 1] // "fromage" Écrire "Total : ", longueur(courses), " articles"

Exemple 2 — Températures de la semaine

temp ← [18, 21, 17, 19, 22, 24, 20] Écrire "Lundi : ", temp[0] // 18 Écrire "Mercredi : ", temp[2] // 17 Écrire "Dimanche : ", temp[6] // 20

Exemple 3 — Modifier une note

notes ← [12, 15, 8, 17, 10] // L'élève à l'index 2 a été réévalué, sa note passe à 14 notes[2] ← 14 Écrire notes // [12, 15, 14, 17, 10]

5Pièges supplémentaires

Index négatif
En JS, tab[-1] renvoie undefined, ce n'est pas le dernier élément. Pour accéder au dernier : tab[tab.length - 1].
Tableau vide
Un tableau vide [] a une longueur de 0. Accéder à tab[0] sur un vide renvoie undefined.
Types mélangés
En JS, on peut mettre des types différents dans un tableau : [1, "abc", true]. Mais c'est une mauvaise pratique — un tableau = un seul type.
Copie par référence
En JS, tab2 ← tab1 ne copie pas — les deux variables pointent vers le même tableau. Modifier tab2 modifie tab1 aussi.
Confondre [] et {}
[ ] = tableau (index numérique). { } = objet/dictionnaire (clé-valeur). Deux structures très différentes (voir Leçon 18).
Modifier la longueur
Ne jamais faire longueur(tab) ← 10. La longueur se lit, elle ne se modifie pas directement. On ajoute ou retire des éléments.
